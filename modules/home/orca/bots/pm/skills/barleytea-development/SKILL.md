# 開発依頼を進める

1. 依頼に挙がったIssueやPRを読み、対象リポジトリ、既存担当、作業中のワークスペースを確認する。着手済みの作業は既存担当に引き継ぐ。
2. 成果物、変更範囲、完了条件、検証方法を定める。並行作業は変更範囲が重ならない単位に分け、依存する作業は先行結果を確認してから渡す。
3. ワーカーを起動する前に `orca skills get orchestration` で、そのバージョンの起動方法を確認する。LinuxでCLI名が `orca-ide` の場合は読み替える。対象、依頼の背景、変更してよい範囲、検証方法、報告してほしい根拠を依頼書に記載する。
4. 報告を完了条件と照合し、実際の差分とテスト結果を確認する。重要な変更は、必要に応じて実装から独立した確認を依頼する。追加修正は既存担当に返す。
5. 依頼者に結果と根拠、未確認の点を伝える。外部への公開、PRの承認やマージは依頼で認められた範囲で行う。
