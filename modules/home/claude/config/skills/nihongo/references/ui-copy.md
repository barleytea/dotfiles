# UI・プロダクト文言

## 原則
- 文法の美しさより、ユーザーが迷わず操作できることを優先する。
- 画面上の用語は一貫させる。同じ機能を画面ごとに別の名前で呼ばない。
- ボタンは原則として動作が分かる表現にする（例：保存する、変更を確認する）。
- 状態表示は、現在どうなっているかを具体的に示す。
- エラーは「何が起きたか」「ユーザーが次に何をすればよいか」を伝える。ユーザーを責めない。
- 成功メッセージは、成功した対象や次の状態が分かるようにする。
- 専門用語は対象ユーザーの知識に合わせる。開発者向け画面では用語を不用意に言い換えない。
- 分からない仕様（保存されるか、いつまで使えるか）は断定しない。「未定」のまま空けず、断定しない文言で書いて出す（入力中の内容は残っていない場合があります）。何が決まれば書き替えられるかを一言添える。
- 「！」を重ねない。
- プッシュ通知は、タイトルで何が起きたかを言い、本文ではタイトルを繰り返さずに、相手が次にすることを、命令に聞こえない言い方で短く書く（お忘れなくご返却ください、ご確認をお願いします）。アプリにあるか分からない機能（延長できます）は断定しない。

## 出力時
必要に応じて、画面名・表示箇所・文言・補足を表にする。短いUI文言を長い説明にしない。注記は必要なものだけにする。
文字数制限がある場合は必ず守り、短縮しても意味を失わないようにする。
