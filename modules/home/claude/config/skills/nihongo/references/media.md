# 載る場所ごとの記法

記法が表示されるかどうかは、載る場所で決まる。分からない時は、記法が無くても読める形にする。

| 載る場所 | 形 |
|---|---|
| チャットの返事 | Markdownが表示される。短い返事は文だけで書く。メールやLINEの下書きをコードブロックで囲まない |
| メール本文 | Markdownは表示されない。太字の記号、見出しの記号、表を使わない。区切りは空行、並べる時は「・」、値は「日時：」の行にする。3〜4行ごとに空行を入れる |
| LINE・SMS | 記法なし。1〜2文で改行する。長い話を1通に詰めない |
| Slack | 見出しと表は使わない。太字、箇条書き、短い段落で書く |
| Markdownの文書（README、Issue、技術文書） | 改行1つだけでは行がつながって1段落に表示される。値を1行ずつ並べる時は箇条書き（「- 」）にする。見出しの後と段落の間は空行を入れる |
| Word・Docs・PDFの文書 | 見出しを立てる。経緯や理由は文でつなぎ、箇条書きは独立した項目だけにする |
| スライド | 1枚に主張は1つ。文末は体言止めか短い言い切りでそろえる |
| 表・スプレッドシート | 1つのセルに値は1つ。列名は名詞にし、単位が分かっていれば列名に入れる。セルに文を書かない |
| 画面の文言 | 記法なし。文字数の制限を守る |
| コードのコメント・コミット・PR | そのリポジトリの言語と書き方に合わせる |
| 読み上げ原稿 | 括弧や記号に頼らない。耳で聞いて分かる形にする |

下書きをチャットで渡す時は、下書きの部分だけ載る場所の記法で書く。メールの下書きに太字の記号を残さない。
